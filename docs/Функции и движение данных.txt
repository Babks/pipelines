ФУНКЦИИ И ДВИЖЕНИЕ ДАННЫХ
Действующая версия ВТД Аналитика

1. ЗАПУСК
main() в desktop.py: находит собранный frontend, создаёт случайный токен и свободный локальный порт, запускает uvicorn в отдельном потоке. Затем открывает окно pywebview. При закрытии окна останавливает сервер. Инженерных расчётов эта функция не выполняет.
build_desktop.py: вызывает PyInstaller для упаковки Python, модулей и frontend/dist. Собирает приложение для той ОС, где запущен; Windows-сборка не является Linux-сборкой.

2. ЧТЕНИЕ EXCEL — services/workbooks.py
read_workbook(data): принимает байты XLSX. Проверяет ZIP-размер, листы anom/weld, названия и обязательные колонки. Пропускает пустые строки. Возвращает словарь двух таблиц; у строки есть _excel_row и _sources с адресами ячеек и признаком формулы. Формулы не исполняет. WorkbookError сообщает об ошибке структуры книги.

3. ПОДГОТОВКА И РАСЧЁТ — services/analysis.py
text(value): приводит идентификаторы к текстовому представлению через старый модуль.
number(value): пытается прочитать число; при невозможности возвращает None. None означает отсутствие пригодного числа, а не ноль.
context(row): формирует ключ id_mu/pass_vtd/n_tube. Если часть ключа отсутствует, расчёт нельзя однозначно связать с трубой.
import_project(data, filename): вызывает чтение книги, создаёт ID проекта, SHA256 исходного файла, дату и список допущений. Затем вызывает analyze_project.
analyze_project(project): основная координирующая функция. Отбирает CORR/DENT, связывает строки с weld, проверяет дубли и конфликтующие значения, сохраняет источники. Для коррозии определяет взаимодействие, рассчитывает одиночные дефекты или собирает группы. Для вмятин вызывает РМ3 только при сохранённом основании. Возвращает проект с defects/errors/summary. Она не должна скрывать ошибочную строку или подставлять ей правдоподобное давление.

4. ОДИНОЧНАЯ КОРРОЗИЯ — services/legacy_core.py
build_inputs: собирает параметры трубы и дефекта в именованный словарь inputs. Выбранное поле давления задаётся явно.
evaluate_isolation: сравнивает дефект с соседями, возвращает single/interacting/undetermined и сведения о парах.
pair_interaction: проверяет одну пару по осевому и окружному расстояниям. Неизвестная геометрия не равна отсутствию взаимодействия.
calculate_single_defect: проверяет входы и вычисляет геометрию одиночного дефекта, давление и коэффициенты.
_pressure_for_geometry: общий вычислительный блок Q и разрушающего давления для заданных длины и глубины.
_sto_safety_factor: возвращает R1, gamma и K_СТО.
_tz_safety_factor: вычисляет отдельный K_ТЗ для категорирования.
_danger_threshold_mpa: вычисляет ((1+K_ТЗ)/2)*p.
calculate_danger_single: проверяет A по текущему состоянию, затем прогноз и срок обследования; возвращает категорию и промежуточные величины. Ограничение: эта ветвь не пересобирает взаимодействия с соседями при росте.
_solve_tno_years: численно ищет достижение порогового давления. Отсутствие решения в интервале поиска не означает бесконечный ресурс.
Файл содержит также старые CLI-функции. Наличие функции в нём не означает, что она вызывается рабочим интерфейсом; активные вызовы находятся в analysis.py и новых модулях.

5. ГРУППЫ — services/spatial_groups.py
merge_projection(rows): сортирует и объединяет пересекающиеся осевые интервалы. Сохраняет участников, максимумы глубин по стороне стенки, затем суммирует EXT/INT.
sequence_candidates(items, diameter, wall, tensile): перебирает все непрерывные наборы n..m. Для каждого вычисляет общую длину, эффективную глубину, Q и давление. Возвращает список вариантов с ID участников.
calculate_spatial(rows, inputs): строит окна и линии проекции, выбирает подходящие дефекты, вызывает объединение и перебор. Возвращает минимальное давление, опасную комбинацию и трассировку по окнам/линиям. Положение первой линии, окна и правила границ — документированные соглашения, требующие отдельной верификации.

6. ПРОГНОЗ ГРУПП — services/group_forecast.py
forecast_group(rows, seed_ids, inputs, years): увеличивает длину и глубину исходных дефектов, заново проверяет взаимодействия и включает новых соседей. Затем повторяет пространственный расчёт. Достижение глубиной толщины стенки фиксируется отдельно.
group_category(rows, seed_ids, inputs, current_pressure): вычисляет K_ТЗ и порог, проверяет текущую A, прогноз на три года и срок обследования. Возвращает категорию и детали прогноза.

7. МАЛЫЕ ВМЯТИНЫ — services/dent_rm3.py
calculate_rm3: принимает диаметр, толщину, длину, ширину, глубину и подтверждение отсутствия вторичных повреждений. Проверяет область малых вмятин, вычисляет геометрию дуги и деформацию либо применяет доступное условие малой неглубокой вмятины. Для предварительных A/B возвращает awaiting_rm2 и пустую итоговую category. Разрушающее давление РМ3 не рассчитывает.

8. ХРАНЕНИЕ — storage.py
data_directory(): выбирает каталог по VTD_DATA_DIR либо правилам Windows/Linux.
connection(): открывает SQLite и создаёт таблицу projects, если её ещё нет.
save_project(project): записывает ID, имя и JSON проекта параметризованным SQL-запросом.
list_projects(): возвращает краткий список ID/имён для выбора в интерфейсе.
get_project(project_id): возвращает сохранённый JSON или None.

9. API — main.py
local_session: проверяет заголовок токена локального сеанса для /api/.
health: сообщает состояние сервиса.
public: исключает полные tables из ответа интерфейсу, сохраняя сведения об источниках в карточках.
require_project: находит проект либо возвращает HTTP 404.
projects/project: список проектов и один выбранный проект.
import_excel: проверяет расширение/размер, запускает импорт, сохраняет проект; ошибка входа возвращается клиенту.
recalculate: повторяет анализ сохранённых исходных таблиц и записывает результат.
export: формирует XLSX с результатами и допущениями. Текущий экспорт агрегирует группы; не является полным протоколом всех промежуточных комбинаций.
assess_dent: сохраняет текстовое основание для РМ3 и пересчитывает проект. DentAssessment проверяет длину текста, но не доказывает достоверность введённого пользователем документа.

10. ИНТЕРФЕЙС
api.ts: request отправляет запросы с токеном; downloadReport получает XLSX и инициирует сохранение.
ImportWorkbook: выбор файла, состояние загрузки, ошибки и отправка multipart-запроса.
Workbench: хранит проект, выбранную запись, вкладку, фильтры и пагинацию. load открывает сохранённый проект; imported принимает новый; recalculate вызывает пересчёт; rm3 отправляет основание для модели. Отфильтрованный массив строится useMemo. Инженерные формулы здесь не вычисляются.
CalculationCard: показывает исходные ячейки, выбранные входы, шаги и результат. Закрытие панели не сбрасывает фильтры. Поле evidence хранит введённое основание для РМ3.
Navigation: переключает страницы рабочей области.

11. ПРИМЕР ПУТИ ОДНОГО ЗНАЧЕНИЯ
osob_dlina в anom → read_workbook сохраняет число и адрес ячейки → build_inputs формирует length_mm → функция расчёта использует length_mm при вычислении Q → результат попадает в steps → CalculationCard отображает его. Поэтому на вопрос «откуда взялось число?» нужно назвать и исходную ячейку, и преобразование, а не только строку таблицы интерфейса.

Этот справочник описывает ответственность функций, их входы и выходы. Для подробной последовательности формул читать «Алгоритм расчёта коррозионных дефектов.txt».
