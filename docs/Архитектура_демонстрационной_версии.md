# Архитектура

Frontend получает синтетические записи из `frontend/src/data/demo.ts`. Чистая функция `filterDefects` независима от React и расчётного слоя. Тип `Defect` — discriminated union: `single`, `group`, `dent`. Группа содержит список одиночных участников. В `CalculationResult` нет ветки успешного расчёта: только `not_connected`, `missing_data`, `awaiting_rm2`, давление и окончательная категория всегда `null`.

`demoCategory` отделена от `result.finalCategory`; предварительная категория РМ3 существует только в `awaiting_rm2`. Нельзя получить итоговое давление из демокатегории. `effectiveGeometry` и `criticalCombination` группы имеют значение `null`.

`App` владеет контекстом проекта/участка, фильтрами, страницей, выбранной записью и файлом. `Navigation`, `DefectFilters`, `DefectTable`, `DefectDrawer`, варианты карточек и `UploadPage` независимы. Закрытие Drawer меняет только флаг видимости. Навигация на экран загрузки не сбрасывает фильтры. Смена контекста сбрасывает фильтры и выделение. Неверная комбинация фильтров честно показывает пустой список.

Vite на `127.0.0.1:5173` проксирует `/api/health` в `127.0.0.1:8000/health`. Реестр не зависит от успешности проверки сервиса. HTTP-запрос ограничен четырьмя секундами; при неудаче доступны пояснение и повторная попытка. Внешние API, шрифты и аналитические сервисы не используются.

FastAPI предоставляет только `/health` и автоматически сформированную API-документацию. Будущие модули разделены по назначению:

| Модуль | Назначение модуля |
|---|---|
| excel_import | Чтение листов, проверка единиц и схемы, связь с трубой |
| corrosion | Применимость и одиночная коррозия |
| groups | Взаимодействие, полная геометрия §7.1, перебор §7.2 |
| dents | Утверждённые РМ1–РМ3 и зависимости вычислений |
| categorization | Отдельное категорирование по ТЗ |
| contracts | Явный статус отсутствующего расчёта |

Заглушки возвращают `not_connected`, импорт выбрасывает понятную ошибку `CalculationNotConnectedError`. В будущем следует согласовать DTO и нормативные источники перед реализацией API импорта/расчётов. Backend не принимает файлы в этой версии.

Поддержка платформ: обычные Node.js/Python процессы; запуск не требует shell-specific команд в приложении. `start.py` использует `subprocess` без shell, выбирает путь venv по платформе, проверяет занятость портов, открывает локальную страницу и останавливает оба сервиса. Нативная упаковка оставлена за пределами этапа 1.
