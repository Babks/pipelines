## 1. Что происходит при запуске

`pnpm dev` читает script `dev` из package.json и запускает Vite. Vite отдаёт index.html, в котором есть пустой `div` с ID `root` и ссылка на `src/main.tsx`. В разработке Vite преобразует TS/TSX в исполняемый браузером JavaScript. Сам браузер TypeScript не выполняет.

`document.getElementById('root')!` находит этот div. Восклицательный знак убеждает компилятор, что элемент существует; это не проверка в браузере. Если удалить div из index.html, утверждение не спасёт приложение.

`createRoot(...).render(...)` создаёт корень React и отображает дерево компонентов. `StrictMode` добавляет проверки в разработке. Он может повторно запускать цикл эффектов; это объясняет отменённый первый health-запрос и не означает наличие двух backend-серверов.

`ConfigProvider` — компонент Ant Design. Он передаёт дочерним элементам тему и русскую локаль. Цвет, радиус углов, шрифт в theme — параметры оформления. `ErrorBoundary` показывает запасной экран при ошибке рендера потомков. Он не заменяет try/catch для всех асинхронных операций.

`pnpm build` сначала запускает TypeScript-проверку, затем сборку Vite в dist. Успешная сборка означает согласованность типов и возможность собрать ресурсы, но не инженерную корректность.

## 4. Типы и отсутствие данных

`Defect = SingleCorrosion | GroupCorrosion | Dent` означает: объект имеет один из трёх вариантов. Поле `kind` различает варианты. После проверки `d.kind === 'group'` TypeScript знает, что у d есть members. Это называется сужением типа по признаку.

Аналогично `result.status === 'awaiting_rm2'` открывает доступ к preliminaryDemoCategory. В других вариантах такого поля нет.

`null` — явно заданное отсутствие значения. `undefined` обычно возникает у необязательного поля с `?`. В фильтрах undefined означает «не ограничивать», а у глубины null означает «исходное значение отсутствует». Ноль — самостоятельное числовое значение, его нельзя подставлять вместо неизвестного.

`import type` и интерфейсы удаляются при сборке. Они не проверят полученный в будущем JSON. Для реального импорта нужны отдельные проверки схемы и значений, а на Python-стороне — входные модели и нормативные проверки.

## 5. Как state превращается в интерфейс

`useState(initial)` возвращает пару `[value, setter]`. Первое — значение для текущего рендера, второе планирует обновление. Setter не следует воспринимать как немедленное присваивание локальной переменной. React выполнит новый рендер с новым значением.

В App хранятся экран, проект, участок, вкладка, фильтры, выбранный объект, видимость панели, номер/размер страницы и выбранный файл. Всё это — память открытой страницы; localStorage и БД не используются. После обновления браузера состояние теряется.

Поток записей: `demoDefects → scoped → filtered → DefectTable`. scoped отбирает проект и участок; filtered добавляет вкладку и все условия; Table сортирует и показывает нужную страницу.

`useMemo` предотвращает лишнее повторное вычисление при неизменных зависимостях. Это оптимизация, а не обязательная часть алгоритма. С 30 объектами выигрыш невелик; корректность не должна зависеть от кеша.

Числа на вкладках берутся из scoped, поэтому отражают участок целиком. «Найдено объектов» берётся из filtered и учитывает фильтры. Участники групп отдельно в эти количества не добавляются.

## 6. Пройдём одно действие целиком

Пользователь вводит `demo-0001`:

1. Input вызывает onChange с событием e; `e.target.value` содержит текст.
2. DefectFilters создаёт новый объект `{...value, query: текст}` и вызывает переданный onChange.
3. В App этот callback — updateFilters: он сохраняет фильтры и устанавливает страницу 1.
4. На новом рендере useMemo вызывает filterDefects с новыми filters.
5. Функция убирает крайние пробелы, приводит регистр и проверяет includes.
6. Новый массив передаётся в dataSource Table. Сама запись при этом не меняется.

Пользователь нажимает запись:

1. onRow возвращает обработчик onClick; он вызывает onSelect(d).
2. В App onSelect — функция select: она сохраняет d и устанавливает drawerOpen=true.
3. DefectTable получает selectedId и добавляет CSS-класс выбранной строке.
4. DefectDrawer получает выбранный объект и выбирает компонент по kind.
5. Закрытие меняет только drawerOpen=false. filters, current и selected сохраняются.

Кнопка ID останавливает всплытие события через stopPropagation, иначе клик обработался бы и кнопкой, и родительской строкой.

## 7. Фильтрация и сортировка — разные операции

`filter` возвращает только подходящие записи. Условия соединены `&&`: все выбранные ограничения должны выполниться. Внутри проверки одиночного фильтра `!filters.pipe || ...` означает: либо фильтр не выбран, либо запись ему соответствует.

Для поиска участника используется `members.some(...)`: достаточно одного совпадения. Возвращается группа, внутри которой можно раскрыть участника. Другие фильтры при этом применяются к самой группе, а не отдельно ко всем её участникам.

Числовая сортировка передаёт Table функцию `(a,b) => a[key] - b[key]`. Отрицательный результат ставит a перед b при сортировке по возрастанию. Для null используется временный -1 только в сравнении; неизвестное исходное значение остаётся null. При сортировке по убыванию порядок меняет библиотека.

Категория null сравнивается как Z, чтобы при возрастании оказаться после A/B/C. Номера труб в таблице сравниваются localeCompare с numeric:true. Список options трубы в App пока имеет обычный строковый sort — это отличается от сортировки колонки.

Пагинация работает в памяти браузера. Серверной загрузки страницы нет. rowKey=id обеспечивает устойчивую идентификацию строк при перестановке. Номер массива как ключ здесь был бы хуже, поскольку меняется при сортировке.

## 8. Как читать JSX и props

`<Component prop={expression} />` вызывает React-компонент с props. Значение в фигурных скобках — JavaScript, текст между тегами — отображаемое содержимое. `className` задаёт CSS-класс; `aria-label` — доступное имя для вспомогательных технологий и тестов.

`condition ? A : B` выбирает один вариант. `condition && <Tag/>` показывает Tag только при истинном условии. `items.map(...)` создаёт список элементов, `key` помогает React сопоставить их между рендерами.

В `Descriptions` items — массив описаний: key идентифицирует пункт, label задаёт подпись, children — содержимое значения. В Table title — заголовок, dataIndex — имя поля, render — функция оформления ячейки. Ни render, ни children сами по себе не означают вычисление инженерного результата.

У Tabs `key={defect.id}` заставляет React создать новый экземпляр при выборе другого дефекта; поэтому другая карточка начинает с «Данные». При закрытии и повторном открытии той же записи ключ прежний.

`onChange={handler}` передаёт функцию. `onChange={() => handler()}` передаёт новую функцию-обёртку. `onChange={handler()}` обычно ошибочно вызовет функцию прямо во время рендера.

## 9. Excel: где заканчивается текущая реализация

Браузер выдаёт объект File с name и size. validateFileSelection проверяет расширение регулярным выражением, ненулевой размер и предел 50 × 1024 × 1024 байт. Название «50 МБ» упрощённое, технически это 50 МиБ.

`beforeUpload` возвращает false — штатный способ остановить автоматическую отправку Ant Design. Файл остаётся в React state, его имя показывается пользователю. `showUploadList=false` отключает стандартный список, потому что выбранный файл отображается собственным блоком.

Содержимое не читается ни FileReader, ни Excel-библиотекой. Нет проверки anom/weld. Произвольный непустой файл с расширением xlsx пройдёт проверку метаданных: это ожидаемое ограничение. E2E специально использует такой файл и проверяет честную надпись «Проверка содержимого не выполнялась».

## 10. Frontend → backend

ServiceStatus делает `fetch('/api/health')`. Запрос идёт на текущий frontend origin. Vite proxy перенаправляет его на `http://127.0.0.1:8000/health`, удалив `/api`. Поэтому браузеру не требуется прямой запрос на другой порт и настройка CORS для этого сценария. Proxy предназначен для dev-сервера, его нельзя автоматически считать частью произвольного production-хостинга.

FastAPI получает GET /health и вызывает health(). Возвращённая Pydantic-модель сериализуется в JSON. Поля calculations_connected и excel_import_connected равны false. status=ok подтверждает лишь доступность API.

Frontend проверяет и успешность HTTP, и поле status в JSON. Сетевой сбой, неожиданный JSON и HTTP-ошибка приводят к offline. AbortController отменяет запрос через четыре секунды. Флаг mounted не позволяет старому запросу обновить состояние после удаления компонента или перезапуска эффекта. finally убирает таймер. Кнопка повтора увеличивает attempt, зависимость эффекта меняется и запрос выполняется снова.

Этот запрос не содержит дефектов и не меняет реестр. 

## 11. Python и заглушки

`@app.get` — декоратор регистрации маршрута, а `app = FastAPI(...)` — объект приложения. Сеть обслуживает Uvicorn. `backend.app.main:app` в команде означает «импортировать модуль backend.app.main и взять переменную app».

`NotConnectedResult` — Pydantic-модель ответа заглушки. Она допускает только not_connected и отсутствующие давление/категорию. Функции демонстрационных сервисов возвращают этот объект.

import_workbook принимает Path для будущего API, но немедленно выбрасывает CalculationNotConnectedError. Это предотвращает ложный успешный результат. Исключение наследует NotImplementedError.

start.py использует стандартную библиотеку: argparse для аргументов, pathlib для путей, shutil.which для Node, socket для портов, subprocess для процессов, urllib для HTTP-готовности, webbrowser для открытия страницы. Аргументы процессов передаются списками без shell. finally останавливает запущенные дочерние процессы. Это launcher, не сервер и не расчётный модуль.

## 12. Стили и числа в интерфейсе

CSS отвечает за внешний вид. Тема Ant Design задаёт общие токены, классы styles.css уточняют размеры и компоновку. Более поздние правила по Figma могут перекрывать ранние при одинаковой специфичности. Это известная особенность текущего накопленного CSS; следующий этап уборки — объединить дублирующиеся правила.

72 — высота шапки, 692 — ширина панели, 1920×1080 — целевое окно. Такие числа относятся к вёрстке. Длина дефекта и давление хранятся в data, а не CSS. Цвет категории — только способ отображения уже заданного значения.

`mask=false` у Drawer отключает затемнение. Положение панели начинается под шапкой. Неподключённый «Пересчитать» имеет disabled; подпись и Tooltip объясняют причину. Это намеренный запрет действия, а не сломанная кнопка.

## 13. Конфигурация и проверки

package.json содержит scripts и зависимости. pnpm-lock.yaml закрепляет разрешённые версии, в том числе транзитивные. Его не следует объяснять как написанный вручную прикладной алгоритм. node_modules — установленный код библиотек; dist — результат сборки. Эти каталоги не являются основным местом правок.

tsconfig.json включает strict и noEmit: компилятор проверяет типы, а выпуском JS занимается Vite. moduleResolution=Bundler соответствует использованию сборщика. JSX преобразуется в вызовы React. skipLibCheck пропускает полную проверку деклараций библиотек, а не отключает строгие проверки нашего кода.

Vitest проверяет чистые фильтры и компоненты в jsdom. jsdom моделирует DOM, но не полноценный движок отрисовки. setup.ts добавляет отсутствующие API. `vi.fn()` позволяет проверить вызов обработчика. Testing Library ищет элементы по ролям/подписям, userEvent имитирует действия.

Playwright открывает настоящий Chromium, проверяет вкладки, сортировку, группы, карточки, файл и геометрию экрана. В этих E2E health подменён через route.fulfill для независимости от Python. Следовательно, успешный E2E не доказывает работоспособность backend.

pytest TestClient вызывает настоящее FastAPI-приложение внутри процесса. Тесты заглушек проверяют, что они не возвращают выдуманные давление и категорию. Это тесты программных контрактов, а не нормативных примеров.

## 14. Словарь синтаксиса, который встретится почти в каждой строке

| Запись | Объяснение |
|---|---|
| import / export | импорт и экспорт между модулями |
| const | запрет переприсвоения переменной; сам объект не становится глубоко неизменяемым |
| let | переменная, которой можно присвоить другое значение |
| : Type | аннотация TypeScript, отсутствующая в исполняемом JS |
| => | стрелочная функция |
| {...obj, field: value} | поверхностная копия объекта с заменой поля |
| [key]: value | вычисляемое имя свойства объекта |
| { value, onChange } | деструктуризация объекта props |
| [state, setState] | деструктуризация массива результата useState |
| ?. | безопасный доступ, если слева null/undefined |
| ?? | значение справа только при null/undefined слева; ноль не заменяется |
| !value | логическое отрицание |
| value! | утверждение TypeScript об отсутствии null/undefined; не runtime-проверка |
| as Type / as const | подсказка типизации; не конвертация и не валидация |
| && / \|\| | логическое И/ИЛИ с коротким замыканием |
| === | строгое равенство без автоматического приведения типов |
| % | остаток от деления |
| map / filter / some / find | преобразовать / отобрать / проверить наличие / найти первый |
| async / await | работа с Promise; не превращает JS в отдельный поток |
| try / catch / finally | выполнить / обработать ошибку / выполнить уборку независимо от исхода |
